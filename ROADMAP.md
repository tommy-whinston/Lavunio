## 1. Видение продукта

Цель — сделать **Steam для Minecraft-режимов**: не просто список сборок, а полноценную платформу, где:

- игрок открывает каталог, ищет режимы, смотрит скриншоты, отзывы, обновления и авторов;
- добавляет режимы в библиотеку, устанавливает, обновляет и запускает их в один клик;
- видит свой прогресс, наигранное время, любимые режимы и коллекции;
- автор публикует режим, загружает сборку, выпускает версии и видит статистику;
- магазин модерирует контент, обрабатывает жалобы и защищает игроков;
- лаунчер не зависит от GitHub и умеет качать большие сборки с CDN, с докачкой и проверкой целостности.

### Главные сущности

```text
Автор / команда
      ↓
Режим (игра)  ── теги, обложки, скриншоты, описание
      ↓
Релиз (версия) ── changelog, дата, канал stable/beta
      ↓
Файлы релиза  ── ZIP / части, sha256, размер, манифест
      ↓
Игрок ── библиотека, установка, запуск, отзывы, коллекции
```

### Не цели на первом этапе

- Полный клон Steam с чатом, голосом, торговлей и семейным доступом.
- Платные режимы, выплаты авторам и налоги — только после стабильного магазина и модерации.
- Кроссплатформенность (сначала Windows 10/11).
- DRM и античит.
- Внешние OAuth-провайдеры (Microsoft и др.) — после стабилизации Lavunio ID.

## 2. Где мы сейчас (0.4.44)

### Что уже работает

- Лаунчер на Tauri 2 + Rust.
- Каталог режимов в отдельном репозитории `tommy-whinston/Lavunio-Catalog`.
- Автор и соавторы у режима, отображение на карточке и в деталях.
- Магазин, библиотека, поиск, фильтры, сортировка.
- Установка, обновление, удаление и запуск сборок.
- Скачивание ZIP и частей, проверка sha256, безопасная распаковка.
- Автоопределение Java, выбор версии под Minecraft.
- Вход через Lavunio ID и собственные скины.
- Настройки ОЗУ, папки игры, окна, Java и JVM-флагов.
- Автообновление лаунчера через GitHub Releases.
- Локальные логи и кнопка открытия папки логов в «Дополнительно».
- Smoke-тест лаунчера: `npm run smoke`.
- Публикатор `Lavunio Publisher` на Tauri, публикация через GitHub API.
- Тёмная тема, релизные заметки, установщик NSIS.

### Что мешает назвать это Steam

| Проблема | Почему это важно |
|---|---|
| Каталог — статический JSON на GitHub | Нет поиска, пагинации, модерации, статистики, нормальных релизов |
| Нет backend и базы данных | Нельзя хранить авторов, отзывы, жалобы, статистику, токены |
| Публикатор работает через личный GitHub-токен | Небезопасно и не масштабируется на многих авторов |
| Нет модерации и жалоб | В магазин можно загрузить что угодно |
| Нет отзывов, рейтингов, рекомендаций | Магазин не помогает выбрать режим |
| Нет загрузки с CDN и докачки | GitHub плохо подходит для больших сборок |
| Нет очереди загрузок, паузы и возобновления | Большие режимы качаются неудобно |
| Нет неизменяемых релизов | Нельзя нормально хранить историю версий и откатываться |
| Нет статистики скачиваний и установок | Автор не видит, нужен ли его режим |
| Нет облачных сохранений и достижений | Нет части «Steam-ощущения» |
| Нет подписок на авторов и соцфич | Нет удержания и сообщества |
| Нет CI и полноценного crash-reporting | Релизы проверяются вручную, ошибки сложно собирать |

### Текущая архитектура

```text
Lavunio (Tauri + Rust)
  ├─ src/                 UI: HTML, CSS, JS
  ├─ src-tauri/src/       Rust: команды, сеть, игра, настройки
  ├─ Lavunio-Catalog       публичный GitHub-репозиторий с modes.json и сборками
  └─ Releases              установщики лаунчера

Lavunio Publisher (Tauri + Rust)
  └─ GitHub API            запись modes.json и файлов в Lavunio-Catalog
```

### Карта файлов лаунчера

- `src/index.html` — разметка окон, магазина, библиотеки, настроек.
- `src/app.js` — вся клиентская логика и рендер.
- `src/bridge.js` — мост между JS и Rust-командами.
- `src/styles.css`, `src/theme.css` — стили и тема.
- `src-tauri/src/commands.rs` — Tauri-команды.
- `src-tauri/src/models.rs` — модели `Mode`, `Author`, `Settings`, `Account`.
- `src-tauri/src/net.rs` — каталог, манифесты, скачивание, распаковка.
- `src-tauri/src/game.rs` — Java, установка, запуск, Forge/NeoForge.
- `src-tauri/src/store.rs` — настройки, аккаунты, состояние, кэш.
- `src-tauri/src/update.rs` — обновление лаунчера через GitHub Releases.
- `src-tauri/tauri.conf.json` — версия, окно, NSIS.

## 3. Целевая архитектура

```text
┌────────────────────┐        ┌────────────────────┐
│  Lavunio Launcher  │        │  Lavunio Publisher / Web │
│  Tauri + Rust      │        │  кабинет автора    │
└─────────┬──────────┘        └─────────┬──────────┘
          │ HTTPS / JSON                 │ HTTPS
          ▼                              ▼
┌──────────────────────────────────────────────────┐
│                 Lavunio API                      │
│  Rust + Axum + PostgreSQL + background workers   │
│  каталог, авторы, релизы, отзывы, модерация      │
└─────────┬──────────────────────────┬─────────────┘
          │                          │
          ▼                          ▼
┌────────────────────┐        ┌────────────────────┐
│  PostgreSQL        │        │  R2 / S3 + CDN     │
│  метаданные        │        │  ZIP, обложки      │
└────────────────────┘        └────────────────────┘
```

### Принципы

- Лаунчер **не знает про GitHub** и не хранит GitHub-токены.
- Каталог и файлы приходят из API и CDN.
- GitHub остаётся только для обновлений самого лаунчера.
- Публикатор и веб-кабинет работают через API.
- Все большие файлы — в объектном хранилище, а не в git.
- Релизы неизменяемы: после публикации файлы версии не перезаписываются.
- Любое действие автора и модератора попадает в журнал.

## 4. Модель данных MVP

```text
users              id, username, display_name, email, password_hash, role,
                   minecraft_uuid, skin_url, skin_model, cape_url,
                   email_verified_at, created_at, updated_at
teams              id, slug, name, description, avatar_url, created_at
team_members       team_id, user_id, role

modes              id uuid, slug, title, short_description, description,
                   status, cover_url, author_id, team_id, created_at, updated_at
mode_authors       mode_id, user_id, role, sort_order
tags               id, slug, name
mode_tags          mode_id, tag_id

releases           id uuid, mode_id, version, status, channel,
                   changelog, published_at, created_at
release_assets     id uuid, release_id, kind, url, size, sha256,
                   parts_json, manifest_json

reviews            id, mode_id, user_id, rating, text, status, created_at
reports            id, target_type, target_id, user_id, reason, status, created_at
moderation_actions id, moderator_id, target_type, target_id, action, note, created_at

library            user_id, mode_id, favorite, hidden, added_at
downloads          id, user_id, release_id, status, bytes_done, bytes_total, created_at
installs           id, user_id, mode_id, release_id, installed_at, last_played_at, playtime_secs
follows            user_id, author_id
api_tokens         id, user_id, name, token_hash, scopes, last_used_at, created_at
```

### Обязательные правила

- У режима есть стабильный `uuid` и человекочитаемый `slug`.
- У релиза есть неизменяемый `version` и набор файлов.
- Пути в хранилище не зависят от пользовательских имён:
  `modes/{mode_uuid}/releases/{release_uuid}/build.zip`.
- Все файлы проверяются по `sha256` и размеру.
- Распаковка запрещает path traversal.
- Токены публикатора хранятся только в виде хеша.

## 5. API v1 (MVP)

Публичные:

```text
GET  /v1/health
GET  /v1/catalog?query=&tags=&mcVersion=&loader=&sort=&page=&limit=
GET  /v1/modes/{slug}
GET  /v1/modes/{slug}/releases
GET  /v1/modes/{slug}/reviews
GET  /v1/authors/{slug}
GET  /v1/collections
GET  /v1/news
```

Авторизованные игроки:

```text
POST /v1/auth/register
POST /v1/auth/login
POST /v1/auth/refresh
POST /v1/game/session
PUT  /v1/me/skin
PUT  /v1/me/cape
GET  /v1/me
GET  /v1/library
POST /v1/library/{mode_id}
DELETE /v1/library/{mode_id}
POST /v1/modes/{slug}/reviews
POST /v1/reports
POST /v1/follows/{author_id}
DELETE /v1/follows/{author_id}
```

Публикатор:

```text
POST /v1/publisher/modes
PATCH /v1/publisher/modes/{id}
POST /v1/publisher/modes/{id}/releases
POST /v1/publisher/releases/{id}/assets/upload-url
POST /v1/publisher/releases/{id}/submit
GET  /v1/publisher/modes/{id}/stats
```

Админка:

```text
GET  /v1/admin/moderation/queue
POST /v1/admin/moderation/{id}/approve
POST /v1/admin/moderation/{id}/reject
POST /v1/admin/modes/{id}/hide
GET  /v1/admin/reports
```

Для больших файлов API выдаёт **pre-signed URL** на загрузку/скачивание. Файлы идут напрямую в R2/S3 через CDN.

## 9. Правила для AI-агента

1. **Не выдумывай доступы.** Если нужен сервер, домен, R2-бакет или токен — остановись и напиши в «Открытые вопросы».
2. **Не трогай пользовательские данные.** Установленные режимы, аккаунты и настройки нельзя удалять без миграции.
3. **Не закрывай запущенные игры и лаунчер** без явной необходимости.
4. **Не добавляй технические настройки в UI.** Источник каталога, токены, репозитории и служебные пути — только внутри кода.
5. **Не смешивай задачи.** Один коммит — одна цель.
6. **Сначала прочитай, потом меняй.** Особенно `app.js`, `commands.rs`, `game.rs`, `net.rs`.
7. **Сохраняй стиль.** Тёмная тема, существующие классы, русские тексты, аккуратные отступы.
8. **Не ломай совместимость без плана.** Для перехода на API сохраняй fallback на GitHub-каталог хотя бы на один релиз.
9. **Проверяй сборку.** Не сообщай «готово», если `cargo check` или `node --check` падают.
10. **Обновляй roadmap.** После задачи — чекбокс и запись в журнале.
11. **Не используй GNU-тулчейн для Lavunio Publisher.** Иначе exe падает с ошибкой DLL. Только MSVC через `build-env.bat`.
12. **Не публикуй релиз без установщика.** Проверь, что `Lavunio Setup <версия>.exe` существует и запускается.
